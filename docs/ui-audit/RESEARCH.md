## Как снимались измерения

Три обстоятельства определили метод и стоят того, чтобы быть названными до выводов.

**Первое. Dev-сервер на этой машине не годится для замеров.** При первой попытке лендинг
отрисовался пустым: контент присутствовал в DOM (759 символов, `h1` на месте), но два предка
стояли на `opacity: 0` без запущенной анимации. Причина оказалась не в продукте: `[измерено]`
`elementsWithReactProps: 0` — React ни разу не гидратировал страницу, потому что HMR-сокет
`ws://127.0.0.1:3000/_next/webpack-hmr` не подключается (прокси-окружение машины глушит локальные
WebSocket). framer-motion отрисовал серверное `initial` и заморозил его навсегда. На
продакшен-сборке гидратация проходит штатно: 56 элементов с React-пропсами, герой `opacity: 1`,
появляется `first-contentful-paint`. **Все выводы этого исследования сняты с продакшен-сборки.**

**Второе. Бэкенд поднять не удалось, и это оказалось к лучшему.** Docker-движок не запускается из
сессии без прав администратора: служба `com.docker.service` в режиме `Manual` остановлена, а
`Docker Desktop.exe` завершается сразу, не получив подтверждения UAC. Вместо этого API
перехвачен на уровне браузера в Playwright и отвечает фикстурами (`tools/mock-api.mjs`). Клиент
только декодирует access-токен без проверки подписи (`frontend/src/lib/jwt.ts:23`), а личность
выводит из claims (`store/auth.ts:100`–`:112`), поэтому мока одного `/auth/api/v1/auth/refresh`
достаточно для авторизованного состояния. Это дало то, чего живой бэкенд не даёт: три
детерминированных набора данных — `rich`, `empty`, `extreme` — и возможность вызывать отказы по
команде.

**Третье. Числа исходного брифа перепроверены, и часть из них не подтвердилась.**

| Предпосылка брифа | Результат проверки |

| Пустые состояния могут быть не реализованы | **Опровергнуто.** `[из кода]` реализованы на всех списках без исключения |

## БЛОК 1. Источники визуальной истины

### 1.1 Сколько их и как они расходятся

Источников четыре, и они не образуют иерархию — они конкурируют.

`design-tokens.ts` (256 строк) в шапке объявляет себя «Single Source of Truth» и требует: «ALL
visual styles MUST reference these tokens», «NO inline colors, shadows, or arbitrary values in
components». `[вычислено]` Его импортирует **ноль** продуктовых файлов. Единственный импорт —
собственный тест `frontend/src/test/lib/design-tokens.test.ts:3`. Тест зелёный, и именно поэтому
опасен: он создаёт ощущение, что система токенов работает.

`tailwind.config.ts` (217 строк) содержит **буквальную копию** палитры, радиусов, теней,
z-index и длительностей из `design-tokens.ts` — значения совпадают посимвольно. Плюс то, чего в
токенах нет: кривая `snappy`, отступы 18/88/128, легаси-цвета `background`/`foreground`/`border`/
`input`/`ring`/`card`/`popover`, `darkMode: ["class"]` и шесть keyframes. Шкалы кеглей и весов он
**не** переопределяет — значит, действуют дефолты Tailwind, включая `text-5xl`…`text-9xl` и
`font-thin`…`font-black`, которых в токенах нет. Именно отсюда в продукт попал вес 900.

CSS-переменные в `globals.css:116`–`:183` — это палитра shadcn/ui в `oklch`, никак не связанная с
первыми двумя. `[вычислено]` После перевода в sRGB расхождения такие:

| Переменная | В `globals.css` | В `tailwind.config.ts` | ΔOKLab | Вердикт |
|---|---|---|---|---|
| `--accent` | `oklch(0.97 0 0)` = `#f5f5f5` серый | `#0ea5e9` синий | **0,3215** | разные цвета |
| `--ring` | `oklch(0.708 0 0)` = `#a1a1a1` | `#000000` | **0,709** | разные цвета |
| `--primary` | `oklch(0.205 0 0)` = `#171717` | `#000000` | 0,2046 | разные цвета |
| `--foreground` | `oklch(0.145 0 0)` = `#0a0a0a` | `#171717` | 0,0598 | разные цвета |
| `--background` | `oklch(1 0 0)` = `#ffffff` | `#fafafa` | 0,0149 | заметный дрейф |
| `--border`, `--input`, `--card`, `--popover`, `--secondary` | — | — | **0** | совпадают |

Пять совпадений и пять расхождений под одними именами. Особенно показателен `--ring`: правило
`globals.css:185` применяет `outline-ring/50` ко **всему** дереву (`* { @apply border-border
outline-ring/50 }`), и какой именно цвет получится, зависит от того, через какой механизм он
разрешается.

Четвёртый источник — литералы в компонентах. `[вычислено]` 441 применение hex-цвета в `.tsx`,
98 различных значений, из них **75 значений на 177 применений** не имеют соответствия ни в
`design-tokens.ts`, ни в `tailwind.config.ts`. Плюс 120 применений `rgb()`/`rgba()` (65 различных)
и 383 инлайновых `style={{` в 30 файлах.

### 1.2 Коллизии имён — доказанные собранным CSS

Самое дорогое следствие четырёх источников — два случая, когда одно имя утилиты определено
дважды. `[измерено]` в собранном продакшен-CSS:

```
.ease-spring{animation-timing-function:cubic-bezier(.16,1,.3,1)}
.ease-spring{transition-timing-function:cubic-bezier(.175,.885,.32,1.275)}
```

Первое правило приходит из `tailwind.config.ts:155`, второе — из `globals.css:228`–`:230`. Они
задают **разные свойства**, поэтому не перебивают друг друга, а сосуществуют: элемент с классом
`ease-spring` анимируется по кривой `(0.16, 1, 0.3, 1)`, а переходит по кривой
`(0.175, 0.885, 0.32, 1.275)` — с заметным перелётом. Этой второй кривой нет ни в одном
файле токенов. Класс `ease-spring` стоит в базовом наборе `button.tsx:8` и в `input.tsx:30` —
то есть **каждая кнопка и каждое поле в продукте сегодня переходят по незадекларированной кривой
с перелётом**, а декларированная кривая применяется только к CSS-анимациям.

Второй случай проще и хуже:

```
.shadow-soft-xl{--tw-shadow:0 8px 16px #0000000f, 0 12px 24px #0000000d; ...}
.shadow-soft-xl{box-shadow:0 20px 40px -15px #00000014,0 0 1px #0000000a}
```

Оба правила задают `box-shadow`, побеждает второе — из `globals.css:249`. Значение тени,
объявленное в токенах, мертво.

Третий, более мелкий случай: `.shadow-card` Tailwind разбирает как «тень цвета `card`» (потому
что `card` объявлен как **цвет** в `tailwind.config.ts:104`), выдавая бессмысленное
`--tw-shadow-color:#fff`, а рабочее значение приходит из `globals.css:254`.

### 1.3 Фактические шкалы против объявленных

Это численная мера системности продукта. `[вычислено]`

| Шкала | Значений в токенах | Различных в коде | Применений | Из токенов |
|---|---|---|---|---|
| Радиусы | 8 | **12** | 310 | большинство ✔ |
| Тени | 10 | **19** | 130 | 19 из 130 |
| Длительности | 4 | **38** | 158 | **3 из 158** |
| Кегли | 8 | **22** (10 произвольных) | 380 | 249 из 380 |
| Веса | 4 | **7** | 293 | 186 из 293 |
| Отступы | 4-пиксельная шкала | 21 | 949 | все кратны 4 ✔ |
| z-index | 8 ярусов | **16** | 54 | **1 из 54** |
| Кривые | 4 | **12** | 31 | 6 из 31 |

Радиусы и отступы держатся — это единственные две шкалы, где дисциплина соблюдается. Всё
остальное живёт мимо токенов. Длительности и z-index — предельные случаи: из 158 и 54 применений
соответственно к токенам обращаются 3 и 1.

Тени заслуживают отдельного слова: `shadow-sm` (33), `shadow-lg` (30), `shadow-md` (26),
`shadow-xl` (5), `shadow-2xl` (4) — это **дефолты Tailwind**, а не объявленная шкала
`soft`/`soft-md`/`soft-lg`/`soft-xl`/`hover`/`hover-lg`. Поскольку конфиг расширяет (`extend`), а
не заменяет, дефолты остались доступны и победили 98 к 19.

### 1.4 `!important` и каскад

`[вычислено]` 12 вхождений. Разбор известного случая: `globals.css:50`–`:55` обнуляет
`margin-right`/`padding-right`, которые `react-remove-scroll-bar` (внутри Radix) инжектирует в
`body[data-scroll-locked]`. Решение аккуратное и задокументированное: селектор с префиксом `html`
поднимает специфичность до (0,1,2) против (0,1,1) у инжектируемого стиля, `!important` — «пояс и
подтяжки». **Хрупкость:** решение завязано на приватную деталь чужой библиотеки; смена реализации
`react-remove-scroll-bar` (например, переход на `gapMode: padding` или на CSS-переменную) обойдёт
этот перехват молча. `[гипотеза]` Устойчивее было бы не бороться со сдвигом, а исключить его
причину — но она уже исключена: `overflow-y: scroll` на `html` (`globals.css:28`) держит полосу
прокрутки всегда видимой, и компенсация не нужна в принципе. То есть `!important` компенсирует
компенсацию.

### 1.5 Вердикт по `design-tokens.ts`

Три варианта будущего.

**(а) Сделать источником и генерировать из него конфиг Tailwind.** Выбираю этот. Причина: у
проекта уже есть зафиксированная в шапке файла норма, есть тест на неё, и есть второй домен на
подходе — «Деньги» с собственным языком раскладки, движения и типографики чисел
(`docs/eco/UX-BLUEPRINT.md`). Без единого источника приход второго домена гарантированно породит
пятый и шестой источники цвета: `[гипотеза]`, но прямо подтверждаемая историей — второе поколение
анимаций в `animations.ts:213` уже наслоено на первое, не заменив его.

**(б) Удалить, оставив Tailwind + CSS-переменные.** Отвергаю: это оставляет два источника (конфиг
и `oklch`-переменные) и не решает ни одного из пяти расхождений раздела 1.1.

**(в) Оставить как есть.** Отвергаю: 75 придуманных на месте цветов и 38 длительностей — это
скорость деградации, а не состояние.

### 2.2 Вес 900, которого не существует

`[измерено]` `@fontsource` подключает шесть весов — 300, 400, 500, 600, 700, 800
(`app/layout.tsx:2`–`:7`). Начертания 900 нет. При этом `[вычислено]` `font-black` (900) применён
**104 раза** — это самый частый вес в продукте, чаще `bold` (79) и `semibold` (75).

Что делает браузер: по правилам подбора шрифта при отсутствии 900 берётся ближайшее более жирное
или равное — то есть 800. Проверка прямым измерением: строка «Handgloves Planora 2026» при кегле
200 px даёт ширину **2478,375 px** и на весе 800, и на весе 900 — совпадение до третьего знака.
Отдельно подтверждено, что `document.fonts` содержит только веса 300–800.

Следствия три. Первое: `font-black` и `font-extrabold` визуально неразличимы, а применены 104 и 2
раза — то есть верх весовой шкалы схлопнут. Второе: объявленная шкала весов содержит 400/500/600/
700, значит и 800, и 900 находятся **вне** неё. Третье, самое неприятное: LCP-элементом на
`/dashboard`, `/tasks` и `/tasks/completed` является именно `H3.font-black` `[измерено]` — то
есть самый заметный элемент экрана отрисован весом, который продукт не загружает.

### 2.3 Иерархия заголовков

`[измерено]` на продакшен-сборке:

| Маршрут | Заголовки | Проблема |
|---|---|---|
| `/` | `h1` 72 px/700 | — |
| `/auth/login` | `h2` 36 px/700 → `h1` 24 px/700 | `h2` **перед** `h1` и крупнее его |
| `/auth/register` | `h2` 36 px/700 → `h1` 24 px/700 | то же |

уровня; визуально — что главный заголовок экрана не главный.

Отдельно: `h1` одного и того же размера 24 px на пяти маршрутах отрисован двумя разными весами —
700 на входе и регистрации, 900 (то есть 800) на трёх остальных. Это не иерархия, а разнобой.

### 2.4 Табличные цифры: подозрение снято

Бриф предполагал, что `tabular-nums` может не работать. `[измерено]` прямым замером ширины:
пропорциональные `1111` и `0000` различаются на 114–147 px при кегле 100 px, а с
`font-variant-numeric: tabular-nums` разница становится **ровно 0,00 px** на всех весах от 300 до
900. Фича `tnum` в Plus Jakarta Sans работает. Все 12 существующих применений исправны.

Дефект в другом: применений 12 на продукт, полный дат, счётчиков, процентов и дробей приоритета
«n/5». Числа, которые меняются на месте (счётчик символов, счётчик задач, процент прогресса) и
числа, стоящие в колонку (даты в списке), в большинстве своём набраны пропорциональными цифрами и
потому дёргаются при изменении.

### 3.5 Судьба тёмной темы

`globals.css:15`–`:25` документирует причину принудительно светлой темы подробно и убедительно:
контент лежит на прозрачных поверхностях поверх градиента, спроектированного под белое; без
`color-scheme: light` телефон в системной тёмной теме покажет тёмный холст UA под прозрачными
областями, а текст останется почти чёрным — тёмное на тёмном.

`[измерено]` механизм работает: при системной тёмной теме количество провалов контраста на
лендинге, входе и регистрации **не меняется** ни на одном из девяти вьюпортов, тёмного на тёмном
не возникает.

При этом в коде живут: полный блок `.dark` с 26 переменными (`globals.css:151`–`:183`),
`darkMode: ["class"]` в конфиге и 165 утилит `dark:` — но **всего в двух файлах**:
`app/profile/page.tsx` и `components/todos/task-deletion-badge.tsx`. Это не «тема почти готова»,
а два острова. `[гипотеза]` Если сегодня включить класс `.dark`, сломается всё, кроме этих двух
файлов: переменные переключатся, а 98 % компонентов, которые пользуются хардкодом `bg-white`,
`text-gray-900` и hex-литералами, останутся светлыми.

Вердикт: **заморозить с явной пометкой**. Удалять `.dark`-переменные рискованно — они часть
импортированной палитры shadcn; достраивать тему сейчас бессмысленно, пока 75 цветов придуманы на
месте. Правильный порядок: сначала один источник токенов (БЛОК 1), потом тема как производная.

### 3.6 Цена декоративного градиента

`[измерено]` в продакшен-сборке чанк с `three.js` весит **506,7 КБ** из 2 229,4 КБ всего
JavaScript — **23 %**. Это больше, чем `react-dom` (222,0 КБ) и `framer-motion` (107,4 КБ) вместе
взятые. `[не удалось проверить]` расход батареи и загрузку GPU на реальном устройстве — замеров

Отдельное следствие, которое стоит держать в голове при любом решении: именно этот градиент —
причина принудительно светлой темы. Убрав его, проект получает свободу в теме; сохранив —
платит 506,7 КБ и остаётся светлым навсегда.

## БЛОК 6. Взаимодействие и обратная связь

### 6.1 Отклик

`[не удалось проверить]` численно задержку «нажатие → видимая реакция»: для этого нужен прогон
Playwright с измерением времени до первой мутации DOM на пяти ключевых действиях, а действия

есть **макет не дёргается и приходит быстро** — это надёжная опора для быстрого отклика, если
добавить оптимистичные обновления.

### 6.2 Обратимость

`[из кода]` разрушающие действия защищены подтверждением через `ConfirmDialog`. Отмены после
выполнения нет ни у одного действия. То есть модель «спросить перед» вместо «разрешить отменить

## БЛОК 7. Движение

### 7.1 Два независимых источника движения

`animations.ts` (336 строк) объявляет себя «single source of truth for all motion» и формулирует
четыре правила (`:5`–`:9`): только `transform` и `opacity`; UI-взаимодействия ≤ 300 мс; никаких
`filter`/`blur` и теней в `whileHover`; никакого `transition: all`.

Параллельно живут 13 блоков `@keyframes` в `globals.css` и ещё шесть в `tailwind.config.ts:177`–
`:202`.

### 7.2 Нарушения собственных правил

`[из кода]` сам `animations.ts` нарушает три из четырёх:

| Правило | Нарушение |
|---|---|
| только `transform`/`opacity` | `VARIANTS_INPUT_FOCUS:238` анимирует `boxShadow`; `VARIANTS_CARD_HOVER:303` — `backgroundColor`; `VARIANTS_TEXT_HOVER_DARK:309` — `color` |
| UI ≤ 300 мс | `TWEEN_NAVBAR:208` — 400 мс; `navbar.tsx:187` — 450 мс |
| нет `transition: all` | `[вычислено]` **26 вхождений** `transition-all`, включая `button.tsx:19` и `:25` — то есть в базовом компоненте |

`[вычислено]` четыре из тринадцати CSS-keyframes анимируют некомпозитные свойства:
`skeleton-shimmer:288` (`background-position`), `glow:315` (`box-shadow`),
`genesis_highlight:414` (`box-shadow`, `border-color`), `reply_flash:421` (`background-color`).

Отдельная тонкость, которую важно не спутать с нарушением: правило «никаких теней в `whileHover`»
относится к framer-motion, и `animations.ts:177` прямо предписывает использовать вместо этого CSS
`hover:shadow-*`. Кнопка так и делает (`button.tsx:13`) — это **соблюдение**, а не нарушение.

`SPRING_BURST:193` смешивает `type: "spring"` с `duration: 0.4`, из-за чего `stiffness` и
`damping` игнорируются — конфигурация противоречива.

### 7.3 Разброс значений

`[вычислено]` 38 различных длительностей на 158 применений; из четырёх токенов взято **три**
применения. Самые частые — `duration-200` (29), `duration-150` (19), `duration-300` (11), то есть
дефолты Tailwind. Кривых — 12 различных при четырёх объявленных; кривая `cubic-bezier(0.16, 1,
0.3, 1)` выписана литералом восемь раз при существующем токене `ease-spring`.

`navbar.tsx` — концентрат: `[из кода]` семь литеральных длительностей (0,45 / 0,14 / 0,16 / 0,16 /
0,2 / 0,32 / 0,22) и три собственные пружины (`:30`–`:32` — `stiffness: 550/550/420`), которых нет
в `animations.ts`.

### 7.4 Второе поколение поверх первого

`[из кода]` секция `animations.ts:213` «Enhanced animations for UI/UX overhaul» дублирует уже
существующее, не заменяя его: `VARIANTS_MODAL:115` ↔ `VARIANTS_MODAL_BOUNCE:287`;
`VARIANTS_DROPDOWN:125` ↔ `VARIANTS_DROPDOWN_ENHANCED:323`; `VARIANTS_CARD:145` ↔
`VARIANTS_CARD_EXIT:259`; `TAP_PRESS:184` ↔ `TAP_PRESS_ENHANCED:247`; `HOVER_LIFT:178` ↔
`HOVER_GROW:244`. Это прямая иллюстрация того, как ведёт себя система без единого источника.

### 7.5 `prefers-reduced-motion`

Два механизма: `globals.css:494`–`:502` сжимает CSS-анимации до 0,01 мс, а `MotionConfig
reducedMotion="user"` (`motion-preferences-provider.tsx:18`) глушит framer-motion целиком. Оба
решения аккуратные, и второе — образцовое: одна точка вместо `useReducedMotion()` в каждом
компоненте.

Дыра одна, но существенная: `[из кода]` ни один из двух механизмов не влияет на
`requestAnimationFrame`-цикл WebGL-шейдера в `components/backgrounds/color-bends.tsx`. Для
пользователя с вестибулярными нарушениями фон продолжает двигаться. `[вычислено]` из 39 файлов,
которые анимируют, reduced-motion явно уважают 14 — остальные покрыты глобальным `MotionConfig`,
и это нормально; исключение — именно rAF-цикл, который вне его юрисдикции.

### 7.6 Чего не хватает

`[из кода]` есть: переход маршрута (`template.tsx`), вход карточек, входы модалок, стаггер
списков. Нет: анимации изменения числа (счётчики меняются скачком), перехода «список → деталь» с
общим элементом (карточка задачи и модалка редактирования не связаны визуально), анимации
удаления элемента из списка (есть `VARIANTS_CARD_EXIT`, но связь с `AnimatePresence` в списках не
подтверждена).

Отдельно `[измерено]`: `tasks/page.tsx:74`–`:104` содержит числовой роллер — приём, которого
явно не хватает остальным счётчикам продукта.

(`.woff` и `.woff2`). Легаси-`.woff` не нужен ни одному браузеру, поддерживающему остальной стек, —
это примерно половина из 392,7 КБ на диске. Подмножества `vietnamese` и `cyrillic` при английском
целевом языке избыточны; кириллица подгружается только потому, что в UI осталось 1153 символа
русского текста. `[измерено]` при загрузке лендинга браузер запрашивает 4 шрифтовых файла — то есть
ленивая загрузка по `unicode-range` работает корректно.

Цена `force-dynamic` `[измерено]`: сборка помечает **все 13 маршрутов** как
`ƒ (Dynamic) server-rendered on demand`. Статической оптимизации нет нигде — это ровно то, что
предсказывает ADR-0006, и подтверждено фактом. `[не удалось проверить]` TTFB против SLO-02
(`docs/slo.md:46`, p95 ≤ 400 мс) в продакшен-условиях — локальный замер (51–108 мс) нерелевантен.

`[измерено]` 77 % файлов `.tsx` (62 из 81) несут `"use client"`. При `force-dynamic` это прямой
множитель и на объём гидратации, и на TTFB.

показал, что причина — разворачивание ответа без проверки: `const subsByTime = [...subtasks]`

`[измерено]` отсутствие SignalR-хаба приложение переживает штатно: логирует ошибку подключения и
продолжает работу.

`[не удалось проверить]`: одновременное редактирование с двух устройств, приход реалтайм-события
во время ввода, вставку форматированного текста и RTL, поведение при медленном ответе и обрыве
посередине — всё это требует управляемого бэкенда либо расширения фикстур записью.

<a name="блок-16"></a>
## БЛОК 16. Сравнение с эталонами

**Linear — отклик и дисциплина движения.** Механизм: все мутации оптимистичны и применяются
локально до ответа сервера; анимации ограничены 4–6 длительностями и 2 кривыми; переходы между
списком и деталью связаны общим элементом. Применимо к Planora целиком: CLS уже нулевой, база для
оптимистичности есть. Ограничение `force-dynamic` не мешает — речь о клиентских мутациях.

**Things 3 — скорость захвата.** Механизм: создание задачи — одно поле и Enter, всё остальное
(дата, тег, проект) добирается позже или парсится из текста. В Planora `create-todo-panel.tsx`
(795 строк) предъявляет четыре селектора сразу. Применимо: панель уже автофокусирует поле
(подтверждено тестом `usability-contract.test.tsx`), остаётся убрать селекторы с первого экрана.

**Notion — плотность и вложенность.** Механизм: единая сетка блоков, отступ уровня вложенности —
один токен. Применимо частично: у Planora вложенность ограничена «задача → подзадача», глубже не
идёт, поэтому весь аппарат Notion избыточен. Берётся только идея единого отступа уровня.

**Height / Asana — списки и фильтры.** Механизм: фильтр — часть URL, состояние восстанавливается
перезагрузкой и делится ссылкой. В Planora `[не удалось проверить]`, отражается ли фильтр в URL;
`QUICK FILTER` открывается модалкой, что уже указывает на состояние вне URL. Применимо полностью.

**Superhuman / Raycast — клавиатура как первичный интерфейс.** Механизм: палитра команд покрывает
100 % действий, горячие клавиши показываются рядом с действием, а не в справке. В Planora есть
одна горячая клавиша и подсказка о ней («press C to open») — правильный зачаток. Применимо:
палитра команд поверх существующих действий.

**Apple Reminders — мобильный минимум.** Механизм: на телефоне показывается только то, что нужно
для добавления и отметки; всё управление — свайпом, с крупными целями. Прямо противоположно
текущему состоянию Planora, где `/branch` даёт 51 цель мельче 44 px из 55. Применимо как принцип
сокращения, но требует решения, что делать с богатством ветки.

**Stripe Dashboard — типографика данных.** Механизм: все числа табличные, шкала кеглей короткая
(5–6 значений), приглушённый текст никогда не опускается ниже 4,5:1. Применимо прямо и полностью —
это описание того, чего Planora не делает по всем трём пунктам.

### Что сломается, если не исправить системное

`docs/eco/UX-BLUEPRINT.md` описывает для домена «Деньги» собственный язык раскладки, движения,
типографики чисел и цвета. Сегодня в проекте нет механизма, который заставил бы новый домен
использовать существующие токены: `design-tokens.ts` ничего не контролирует, `tailwind.config.ts`
не запрещает дефолты Tailwind, литералы не отлавливаются линтом.

Предсказание прямое: новый домен принесёт пятую палитру (свою, для денег — зелёное/красное),
шестой источник длительностей и вторую шкалу кеглей для чисел. `[гипотеза]`, но подтверждаемая
прецедентом внутри самого проекта: секция «Enhanced animations for UI/UX overhaul»
(`animations.ts:213`) наслоилась на первое поколение, не заменив его, — ровно тем же способом, и
уже дважды: в движении и в тенях.

(`globals.css:50`–`:55`); клипирование `overflow-x` на `html` и `body`; поведение, описанное в
`docs/features.md`.

### Ловушки очевидных улучшений

| «Очевидное улучшение» | Что сломается |
|---|---|
| Снять `overflow-x: hidden` с `html` | Поедет вбок: 20 необрезанных источников переполнения существуют и сегодня, их держит только клип |
| Удалить `!important` в обходе Radix | Вернётся горизонтальный сдвиг страницы при открытии любого выпадающего списка |

| Удалить неиспользуемые компоненты `ui/` | Просядет покрытие ниже порога 85 % — добирать придётся на живом коде |

<a name="три-вещи"></a>
## Три вещи, которые надо исправить первыми

### 1. Контраст и видимость фокуса

Почему первым: это единственная группа, где дефекты **полностью блокируют** часть пользователей,
и одновременно самая дешёвая. Два поля формы входа не показывают фокус вообще (`outline: solid
2px rgba(0,0,0,0)`), все восемь индикаторов ниже порога 3:1, минимальный контраст текста в
продукте — 1,48:1, а `gray-400` при 2,52:1 используется как цвет текста в девяти местах из
пятнадцати провальных. Исправление не требует перестройки раскладки: это правка палитры, одной
строки в `input.tsx:33` и семи колец в `button.tsx`. Проверяется автоматически зондом, который уже
написан.

### 2. Единый источник токенов

Почему вторым: без него любое исправление из пункта 1 и 3 расползётся обратно. Доказательство
уже есть внутри проекта — второе поколение анимаций наслоилось на первое, дефолтные тени Tailwind
победили объявленную шкалу 98 к 19, а 75 цветов придуманы на месте. И есть точная дата, к которой
это станет дорого: приход домена «Деньги» с собственным языком из `docs/eco/UX-BLUEPRINT.md`.
Работа механическая: сделать `design-tokens.ts` источником, сгенерировать из него конфиг, снять
коллизии `.ease-spring` и `.shadow-soft-xl`, включить линты на литералы.

### 3. Карточка задачи

Почему третьим: это единственный объект, который пользователь видит **в каждой сессии на каждом
устройстве**, и в нём одновременно сходятся шесть дефектов: заголовок обрезается кнопкой удаления;
кнопка удаления безымянна и повторена одиннадцать раз как самый яркий элемент экрана; зона свайпа
недоступна с клавиатуры; заголовок завершённой задачи имеет контраст 2,52:1; подписи набраны
кеглем 9–11 px; приоритет закодирован цветами, которые сливаются при дальтонизме. Починив одну
карточку, продукт чинит свой главный экран, свою главную сущность и шесть строк реестра сразу.
