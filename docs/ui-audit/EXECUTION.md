# Planora — план исполнения проекта интерфейса

Операционный документ. `BLUEPRINT.md` отвечает «каким продукт должен стать», этот — «в каком
порядке это делается и как проверяется каждый шаг».

- Дата: 2026-09-13
- Опорные документы: `BLUEPRINT.md`, `RESEARCH.md`, `DEFECTS.md`, `TARGET.md`
- Базовая линия для сравнения: `docs/ui-audit/tools/scan-*.json`

---

## Правила исполнения

Их следует соблюдать буквально — они выведены из того, что уже сломалось в этом проекте.

1. **Фазы идут по порядку.** Каждая опирается на предыдущую. Фазу 5 нельзя делать до фазы 1:
   унификация компонентов без единых токенов породит седьмой источник цвета — ровно так, как
   секция «Enhanced animations» в `animations.ts:213` наслоилась на первое поколение.
2. **Каждая фаза заканчивается зелёной проверкой.** Команда проверки указана в фазе. Если она
   красная — фаза не закончена.
3. **Коммит на каждую фазу**, по формату из `CLAUDE.md`. Не батчить фазы в один коммит.
4. **Документация — часть фазы.** Изменился компонент — обновляется `docs/features.md`; изменился
   токен — `docs/architecture.md`; поведение — `CHANGELOG.md`.
5. **Покрытие 85 % держится.** Удаление мёртвых компонентов просадит его — добирать на живом коде
   в той же фазе.
6. **Ничего из раздела «Неприкосновенное»** (`BLUEPRINT.md`, часть 15) не трогается без явного
   разрешения владельца.
7. **Замер до и после.** Перед фазой прогнать соответствующий скрипт, после — прогнать снова и
   записать дельту в тело коммита.

### Проверка окружения перед началом

Dev-сервер на машине владельца **непригоден для визуальной проверки**: HMR-сокет блокируется
прокси, React не гидратирует страницу, и любой экран выглядит пустым (`RESEARCH.md`, «Как
снимались измерения»). Работать так:

```bash
cd frontend && npm run build
```

Затем поднять через `preview_start` конфигурацию `frontend-prod` (порт 3200) — она уже добавлена
в `.claude/launch.json`. Все замеры — только против неё.

Для авторизованных экранов бэкенд не нужен: `docs/ui-audit/tools/mock-api.mjs` подставляет данные
на уровне браузера. Три набора: `rich`, `empty`, `extreme`.

```bash
node docs/ui-audit/tools/live-scan.mjs --base http://127.0.0.1:3200 --set private --mock --dataset rich
```
