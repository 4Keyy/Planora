# Repository and Documentation Audit — 2026-10-06

This audit reconciles Planora's documentation with its implementation. The
reference guides now describe observed behavior and identify incomplete
guarantees. Documentation updates do not repair application vulnerabilities,
missing migration history, failing tests or deployment configuration.

The initial tracked revision was `8b072a9f3da0e57e1aecfce0e814d780506b3078`.
Another working session continued changing frontend source and committing
documentation during the audit. Verification results below describe their
individual runs, not an immutable final tree or a production certification.
Existing work and experimental untracked files were preserved. Frontend checks
were rerun at `b2e9c70a5781657dc7f24062d2d965c6c846844f` after the parallel UI
changes; backend source did not change from the initial tested revision.

### Publication follow-up

The subsequent commit/push request included restoring the verification gates.
Fresh GitHub restore logs confirmed that the XML cryptography advisories above
were fatal `NU1903` errors. The [security correction](../../.github/security/cryptography-xml-2026-10.md)
pins `System.Security.Cryptography.Xml` to 10.0.12 through an explicit Auth
Infrastructure reference; auditing remains enabled. Forced solution restore,
Release build with `-warnaserror` and all 972 backend tests passed after the fix.
A fresh solution-wide scan with `--vulnerable --include-transitive` subsequently
reported no vulnerable NuGet packages against the current configured sources.

The new `motion-geometry.ui.spec.ts` resolves four Chromium tests. With browser
binaries installed and explicit localhost URLs, all four were skipped because
the frontend server was unreachable. This is discovery/environment evidence,
not a passing browser-flow result. Dependabot updates are reviewed separately
after the baseline is published; this report's original dependency counts
remain an explicitly dated pre-update scan.

## Documentation corrections

- Removed blanket guarantees for exactly-once event processing, atomic workflows,
  automatic fresh-database creation, complete IDOR protection and production readiness.
- Corrected CSRF registration: Auth, Todo, Category, Messaging and Collaboration
  register the middleware; gateway and Realtime do not. The Auth-only ADR is historical.
- Corrected DTO examples, auth expiry semantics, recovery-code input, viewer/owner
  rules, cache names/TTL, schema constraints and tracked migration descriptions.
- Added Collaboration to service/database/deployment inventories and distinguished
  optional Realtime persistence from active delivery tracking/replay.
- Corrected CD existence versus runnable rollout, service matrices, secret subsets,
  effective listener settings and the limits of the prerequisite checker.
- Corrected telemetry precedence, default-off SQL text capture, actual custom
  instruments and collector-dependent query/alert examples.
- Replaced stale test totals with dated measured results and removed fixed counts
  where future changes would make them misleading.
- Preserved historical plans/research/results with explicit snapshot labels and
  repaired source paths that moved into the App Router `(app)` group.

## Verification boundaries and completion criteria

No production account settings, secrets, public deployment, database migration,
database reset, load run against a live system or external message was executed.
Docker-backed end-to-end and clean PostgreSQL migration tests are not established
by the passing .NET/Next builds. Production collector/network/volume behavior
requires a separate configured environment.

The documentation task can describe these limits accurately; it cannot certify
the application as production-ready while open findings and failing checks
remain. Before a later release, complete the high-priority fixes, regenerate
contracts/migrations, rerun the relevant unit/integration/e2e/dependency checks,
and update this dated report with links to the evidence closing each finding.
