среде зависит от T14, сверки фактической схемы, согласованного окна и разрешения

Auth, Category, Collaboration и Messaging запускаются через общую версионную
подготовку. Она сериализует сотрудничающих исполнителей advisory lock и сверяет
каталог с поддерживаемым профилем до записи версии. Совместимая схема без истории
принимается с сохранением существующих данных. Неизвестная либо непоследовательная
история, частичная схема и расхождения останавливают подготовку. Auth сохраняет
существующие произвольные ID ролей и ссылки UserRoles при принятии схемы. Стабильные
ID и UTC-дата применяются при создании новой схемы. Проверка pending model changes
в Auth снова активна.

## Применение и откат

Проверки выполнялись на принадлежащем аудиту PostgreSQL 16.13 с tmpfs и локальной
привязкой. Восстановление подтверждено для синтетической Category. Состав
эксплуатационного backup (PostgreSQL, Redis key ring, RabbitMQ backlog и avatars)
остаётся воротами T14. Проверка совместимости применима к описанным профилям.
Фактические развёрнутые схемы и права требуют отдельной сверки. Перед применением
нужны остановка конкурирующих DDL-писателей, backup и проверенный restore. Старые
runtime helpers Todo и Realtime сохранены, CLI получил предварительную проверку
каталога и истории. Для самостоятельного межбазового backfill применяются его
собственные предусловия. Автоматический Down после новых записей может потерять
данные, включая поля Collaboration. Использовать согласованный roll-forward либо
проверенное восстановление.

Изменения касаются schema startup и административного CLI. UX и пользовательские
API-контракты вне области, screenshot matrix N/A. T15 получает таблицу профилей,
правила design-time выбора, ограничения adoption и процедуры backup/restore.
