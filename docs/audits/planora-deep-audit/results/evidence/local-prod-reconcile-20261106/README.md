# Локальный Production: согласование существующей схемы

Подготовлено для запроса владельца от 2026-11-06. Владелец отдельно разрешил
применение этого плана; четыре SQL применены к локальным рабочим БД.
Исходный код приложения: `fc2929af3b0b1fec45f4d0d00b4b92bf1197f036`.

## Конкретное действие

На локальном `planora-postgres`, порт `127.0.0.1:5433`, применить только:

| БД | SQL | Изменение |
| --- | --- | --- |
| planora_auth_db | [auth.sql](auth.sql) | Недостающая UserRecoveryCodes и её три индекса; TwoFactorSecret расширяется с 500 до 1024 символов; active-outbox индекс. |
| planora_category | [category.sql](category.sql) | Два недостающих индекса. |
| planora_collaboration | [collaboration.sql](collaboration.sql) | Недостающий индекс soft-delete. Reply-поля уже существуют. |
| planora_messaging | [messaging.sql](messaging.sql) | Outbox Status integer переводится в эквивалентные строки enum; проверенные длины Type/Error; default RetryCount; три индекса. Inbox не меняется. |

Контейнер проверен по immutable ID
`39e6b26c5a67f248eed7957e14059f3613da611587a29b9d0a7af8ba9fb5b1d6`,
Compose project `planora`, volume `planora_postgres_data`.
Перед применением повторить проверку ID, mount, порта, отсутствия конфликтующих
писателей и соответствия SHA-256 одобренных SQL.

SQL используют транзакции, lock timeout 5 секунд, statement timeout 60 секунд,
проверку имени целевой БД и ON_ERROR_STOP. Строки не удаляются и значения
не обрезаются. Неизвестные состояния или слишком длинные значения Outbox
останавливают преобразование. IF NOT EXISTS не заменяет проверку структуры:
после SQL штатный VersionedDatabaseStartup обязан подтвердить всю схему.
История миграций вручную не штампуется; штатное принятие версии происходит
только после проверки эквивалентности каталога.

## Выполненная репетиция

- До старта сохранены шесть PostgreSQL custom archives; формат и количество
  проверены. Восстановлены четыре нужные БД на собственном disposable PostgreSQL.
- Исходные четыре копии воспроизвели отказы штатного schema guard.
- После SQL все четыре guard проходят; повтор SQL и повтор startup также проходят.
- Количество и агрегированные row digests всех 18 существующих таблиц совпадают
  до/после. Единственная новая таблица UserRecoveryCodes пуста.
- Пять синтетических integer-состояний Outbox сохранили значения Pending,
  Processing, Processed, Failed, DeadLettered после преобразования.
- Неизвестные integer/text состояния и превышения Type/Error отвергнуты;
  транзакции с integer ошибками сохранили исходный тип. Финальный guard проходит.
- Независимый source review сравнил таблицу, десять индексов, типы и enum mapping
  с текущей EF-моделью. Репетиция не заменяет разрешения на рабочие БД.

Локальные артефакты и приватные backups находятся в
`.buildcheck/local-prod-20261106/`; их содержимое не включено в Git.
Время блокировок на рабочем объёме не измерялось. Автоматический rollback
данных не предусмотрен; backups не являются полной проверкой восстановления
Redis Data Protection или 2FA.

## Продолжение запуска

После разрешённого применения подтверждена сохранность всех 18 существующих
таблиц уже в рабочих БД; новая таблица пуста. Четыре остановившихся API подняты
теми же функциями launcher с прежней Production-конфигурацией. Все семь
ready и aggregate endpoints отвечают успешно; завершены 24 HTTP-проверки,
включая CSRF/refresh и защищённые маршруты через настоящий Next production
server. Страница входа проверена в браузере, console warnings/errors отсутствуют.

Рабочие сервисы оставлены запущенными. Фоновая retention-очистка отключена
только для текущего запуска, без изменения постоянной конфигурации.
Общий аудит остаётся на паузе до команды владельца; BE-006 в код и схему
не вносился. Вход под аккаунтом и пользовательские CRUD-действия не
автоматизировались. [Итог запуска](../../LOCAL_PROD_20261106.md)
