# T06 — Realtime authorization lifetime

Status: **DIST-004 implemented and verified on two isolated Cloud.ru nodes**.
Other T06 findings stay open.

## Behavior

- Task-room delivery resolves the current Todo audience and uses per-user groups,
  preserving SignalR Redis backplane routing without a new shared registry.
- Join and typing check JWT expiry/security stamp before and after authorization.
  Authoritative access denial evicts the caller; an RPC outage suppresses the event
  without erasing a legitimate membership. Leave/disconnect cannot signal a room
  the caller never joined or no longer has permission to address.
- A node-local hosted monitor checks registered idle sessions every 15 seconds.
  Expiry, stamp revocation and Redis lookup failure abort the socket and remove
  its registration and memberships. Scheduling/Redis latency adds to the interval.
  Group-cleanup failure cannot keep the socket alive. Native authentication-expiry
  closure is enabled as well.
- A silent member revoked from a task can physically remain in a per-user group
  until invocation/disconnect, but fresh audience selection no longer addresses it.
  An event whose actor has already lost access, or whose task was deleted, is
  suppressed if the audience cannot be established. Notification/feed cleanup
  paths and event payloads retain their existing contracts.

## Verification

The original five audience/typing regressions and three idle-session regressions
failed before their corresponding fixes. Final targeted result: **86 passed,
14 skipped, 0 failed**, with .NET SDK 10.0.300 and one build/test worker. The skips
are existing PostgreSQL facts without a provider environment in that targeted run.

Tests cover live audience changes, normal delivery, expiry before/during RPC,
stamp rotation, Redis outage, monitor tick, cancellation, cleanup failure and DI
singleton/hosted identity. Independent review found the initial passive stamp gap;
the monitor closes it and the second review found no new blocker in this scope.

All 14 Realtime PostgreSQL facts passed in the later provider run. The two
Cloud.ru nodes shared the disposable Redis backplane and delivered task activity
and typing only to the current audience after share and friendship revocation.
The sockets closed after JWT expiry, password change and revoke-all. On the
patched backplane a real Redis stop closed both idle sockets in 11.0 seconds.
The protected HTTP route returned `503` during the outage and recovered
after restart. See the [cloud checkpoint](CLOUDRU_20261106.md).

## DIST-012: late notification delivery

Realtime now stores a deletion guard for a task or recipient in the same
PostgreSQL transaction as notification and delivery cleanup. Inserts acquire
the matching locks before checking the guards. A replay or first late event
rejected by the store cannot trigger a push.

On disposable PostgreSQL 16.11, the two new sequential regression tests failed
on the original code, with four rows instead of two in both cases. After the
fix, 109 tests passed without skips, including four deletion cases, concurrent
insert waiting on a cleanup transaction, rollback after an injected SQL error,
and upgrade from the initial managed schema while preserving an existing row.
The generated SQL adds one table and its migration history entry. Reports and
SQL are under `.buildcheck/dist012-case/`.

The released SQL was also applied twice to a network-isolated copy of the
Cloud.ru Realtime backup. Row counts and digests for `Notifications`,
`NotificationDeliveries` and `OutboxMessages` matched the original controls.
The marker table started empty and exactly two history entries were present.
[Migration Scripts](https://github.com/4Keyy/Planora/actions/runs/43624913094)
generated SQL for all six services at `81667d0a`. The production migration
is pending. Historical deletes lack a guard, and a push accepted before
cleanup may already be in flight. Live RabbitMQ and SignalR were outside
these targeted checks.
