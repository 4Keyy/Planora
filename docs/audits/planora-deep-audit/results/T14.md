# T14 — Cloud.ru retention and release verification

## 2026-11-19

The Cloud.ru overlay introduced in `1a9197d2` set `Retention__Enabled=false`
in the shared API environment. The configuration was correct during the restore,
but there was no activation setting for TodoApi after cutover. The scheduler
returns before running any policy when this flag is false. The previous
[Cloud.ru checkpoint](CLOUDRU_20261106.md#continuation) records this setting
after public launch.

Commit [8901021](https://github.com/4Keyy/Planora/commit/8901021aa25c8c7af7c7fc84da090e309d93ceb2)
lets TodoApi run its completed-task policies with an explicit opt-in. The default
is disabled, and an enabled scheduler defaults to counting candidates without
editing them. Physical purges and processed-message retention stay disabled.
The existing policy soft deletes an expired completed branch and stages its
deletion event with the mutation. Expired personal completions are hidden for
their viewer. The deployment recipe is in the
[Cloud.ru runbook](../../../../deploy/cloudru/README.md#completed-task-cleanup).
