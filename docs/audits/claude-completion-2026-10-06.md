## Что Codex доделал

1. Docker Compose передаёт все 34 настройки retention каждому из шести сервисов. Раньше явные
   `Retention__Enabled=false` и `Retention__DryRun=true` могли игнорироваться контейнерами.
2. Расписание использует непрерывную UTC-сетку: интервалы 1–24 часа сохраняются через полночь.
   Раньше настройка 7 часов могла превратиться в 3 часа при смене даты.
3. Удаление аккаунта и `UserDeletedIntegrationEvent` сохраняются атомарно в Auth outbox.
   Подключены стандартные repository, processor, signal и interceptor. Ошибка брокера после удаления
   больше не лишает остальные сервисы события очистки.
4. Удаление аватара выполняется и при ошибке Redis security stamp. Ошибка stamp продолжает
   распространяться; команда не сообщает об успешной ротации, если её не было.
5. Физический purge удаляет аватар до любых зависимых строк. Если файл заблокирован, аккаунт и все
   зависимости остаются для следующего прохода. Другие аккаунты продолжают очищаться; отмена операции
   не превращается в успешный purge.
6. Shared outbox processor и canonical repository соблюдают `NextRetryUtc`. Раньше Pending-записи
   повторялись раньше положенной минуты/пяти минут и исчерпывали попытки за несколько секунд.
7. Обновлены пример конфигурации, API, архитектура, безопасность, база данных, поведение, тестирование
   и CHANGELOG. Добавлены регрессии, которые сначала воспроизводили ошибки, затем прошли после fixes.

Конфигурация и расписание отправлены коммитом `dd781a1`.
Надёжность удаления аккаунта и outbox оформлена отдельным коммитом
`fix(auth): retain cleanup events and retry failed avatar removal` вместе с этим отчётом.

## Что осталось

- Панель поиска — по прямому указанию пользователя оставлена тебе; Codex её не реализовывал.
- Применение новых сборок к уже запущенным сервисам требует их штатного перезапуска. Codex не
  перезапускал действующие сервисы и не менял настоящую конфигурацию. Явные старые disable/dry-run
  значения сохраняют свой смысл; перед включением live cleanup проверь конфигурацию среды.
- Общий Security Scan исходного `8f7018e` падает на ранее документированном `npm-audit`: 7 high и
  3 moderate записи в инструментах разработки. Остальные jobs того прогона прошли. Подробности и
  принятое владельцем ограничение — в [обзоре зависимостей](../../.github/security/frontend-dependencies-2026-10.md).
- Outbox сохраняет прежний лимит попыток. После исчерпания retries запись остаётся в `DeadLettered`
  для расследования и операторского replay; автоматическая очистка её не удаляет.

не отправлено: отсутствует `node_repl`, требуемый доступным скиллом computer-use для управления окнами.
